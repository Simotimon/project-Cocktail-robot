## 레시피와 목표량

차터에서 고정한 레시피 3개를 한 잔씩 만드는 것을 **한 판**으로 본다. 병은 모두 7개다.

| 레시피 | 종류 | 재료(목표량) |
|---|---|---|
| 하이볼 | 빌드 | 위스키 45ml, 탄산수 120ml |
| 진토닉 | 빌드 | 진 45ml, 토닉워터 120ml |
| 다이키리 | 셰이크 | 럼 45ml, 라임 주스 20ml, 설탕 시럽 15ml |

맞춤 주문은 손님이 태블릿에서 목표량을 바꿔서 넣는다. 예: 다이키리 "덜 달게" → 설탕 시럽 50% → 7.5ml.
한 판이 끝나는 때 = 마지막 잔이 앞 탁자의 픽업 칸에 놓인 때.

## ① 요구사항 나누기

| 층 | 내용 |
|---|---|
| Stakeholder | 손님이 태블릿으로 주문한 칵테일 3잔(하이볼·진토닉·다이키리)을 4분 안에, 주문한 양(맞춤 포함)대로, 병을 떨어뜨리지 않고 앞 탁자에 내놓는다. 사람 없이 계속 돌아간다 |
| System | 한 판 240초 이하(잔당 평균 80초 = 240 ÷ 3), 재료마다 목표량 ±10% 이내, 낙하 0, 10판 연속 10판 성공 |
| Subsystem | 아래 표의 기능별 시간을 더하면 240초, 붓는 위치 손끝 오차 10mm 이하 |

### Subsystem 시간 나누기

| 기능 | 한 번 | 횟수 | 합 |
|---|---|---|---|
| 병 꺼내기(집기) | 6초 | 7병 | 42초 |
| 붓는 자리로 이동 | 4초 | 7병 | 28초 |
| 붓기(계량) | 6초(평균) | 7병 | 42초 |
| 병 제자리에 놓기 | 6초 | 7병 | 42초 |
| 바 스푼으로 젓기 | 10초 | 2잔(빌드) | 20초 |
| 셰이커 처리: 뚜껑 닫기 8 + 장치에 넣기 6 + 셰이킹(장치) 12 + 꺼내기 6 + 캡 열기 4 + 거름망으로 따르기 12 | 48초 | 1잔(셰이크) | 48초 |
| 앞 탁자 픽업 칸에 잔 내놓기 | 6초 | 3잔 | 18초 |
| **합계** | | | **240초** |

붓는 양은 MuJoCo에 액체가 없으므로 "기울기 각도 × 시간" 공식으로 계산한다(차터 플랫폼 결정).

## ② 요구사항 표

| ID | 종류 | 요구사항 | 우선 | 확인 | 근거 |
|---|---|---|---|---|---|
| R-01 | 기능 | 주문 데이터의 목표량(기본·맞춤 모두)대로 재료마다 ±10% 이내로 붓는다 | Must | T-01, T-02 | 사용자 목표 "맛이 일정하게"와 맞춤 요청(D01). ±10%는 팀 결정(추정) |
| R-02 | 기능 | 병을 떨어뜨리지 않는다(낙하 0) | Must | T-03 | 무인이라 깨진 병을 치울 사람이 없다 |
| R-03 | 성능 | 한 판(3잔)을 240초 안에 끝낸다 | Must | T-04 | 사람은 한 잔 2\~3분(D01, 추정). 손님이 앞 탁자에서 기다리는 시간이다 |
| R-04 | 기능 | 쓴 병을 원래 칸에 되돌려 놓는다(7병 중 7병) | Should | T-05 | 무인이라 잘못 놓인 병을 바로잡을 사람이 없다 |

| R-06 | 안전 | 팔이 로봇 작업 영역 밖(앞 탁자의 손님 쪽 절반 포함)으로 나가지 않는다(0회) | 안전 | T-07 | 손님이 앞 탁자에서 잔을 바로 받는다 |
| R-07 | 운영 | 실행마다 결과를 logs/results.csv에 한 줄 남긴다 | Should | T-08 | 무인이라 사장이 나중에 기록으로 확인한다. 15일차 통합 검증에서 결과를 채운다 |
| R-08 | 성능 | 같은 주문으로 10판을 연속 실행해 10판 모두 R-01\~R-03을 지킨다 | Should | T-09 | 24시간 무인 운영 목표(D01). 10판은 팀 결정(추정) |

### 판정할 수 없는 말 → 판정할 수 있는 말

| 고치기 전 | 고친 뒤 |
|---|---|
| 맛이 일정하다 | 재료마다 목표량 ±10% 이내 |
| 손님 입맛대로 만든다 | 맞춤 주문의 바뀐 목표량 ±10% 이내 |
| 빠르게 만든다 | 한 판 240초 이내 |
| 사람 없이 계속 돌아간다 | 10판 연속 10판 성공 |
| 손님이 안전하게 받는다 | 작업 영역 밖 0회 |

## ③ 우선순위와 범위 밖

| 우선순위 | 뜻 | 우리 프로젝트 |
|---|---|---|
| Must | 없으면 실패 | R-01 목표량 ±10%, R-02 낙하 0, R-03 240초 |
| Should | 가능하면 한다 | R-04 병 제자리, R-05 셰이커 재시도, R-07 결과 기록, R-08 10판 연속 |
| Could | 여유가 있으면 | 레시피를 설정 파일로 바꾸기(4번째 레시피 추가), 주문에 없는 병을 집으면 실패로 세기, 병 남은 양을 세어 보충 알림, 픽업 칸에 손이 있으면 내놓기 멈추기 |
| Won't | 이번에는 안 함 | 아래 '범위 밖' |
| 안전 | 늘 지킨다(개수에 안 셈) | R-06 작업 영역 밖 0회 |

### 범위 밖(Won't)

얼음 자동 공급, 가니시 장식, 액체 자체의 유체 시뮬레이션, 태블릿 화면·결제·성인 확인, 잔·셰이커 세척(사장이 영업 전·후에 한다), 로봇팔로 직접 셰이킹(셰이킹 장치가 맡는다), 로봇팔 2대 이상(위·아래 2팔 협업은 개선 백로그로, 양팔 로봇은 팔당 드는 무게가 작아 1.2kg 병에 맞지 않음), 실물 로봇

## ④ 판정 함수

R-01\~R-03은 `src/judge.py`의 `judge_episode()`가 판정하고, `tests/test_judge.py`로 확인한다.
R-08(10판 연속)은 판마다 `judge_episode()`를 불러 모두 True인지 본다.

에이전트에게 보낸 요청문:

```
[맥락] CLAUDE.md 와 docs/requirements.md 를 먼저 읽어.
[할 일] src/judge.py 에 judge_episode(targets_ml, poured_ml, dropped, elapsed_s) 를 만들어.
[조건] 요구사항 R-01~R-03 을 그대로 따를 것. 다른 파일은 고치지 마.
[완료 기준] tests/test_judge.py 가 모두 통과. 테스트는 고치지 마.
[보고] 바꾼 파일과 pytest 결과를 알려 줘.
```

확인할 세 가지:

1. 붓지 않은 재료가 있어도 오류 없이 '실패'가 되는가 (`poured_ml[name]`으로 쓰면 KeyError로 멈춘다)
2. 숫자가 요구사항과 같은가: ±10% **이내**(<=), 낙하 0, 240초 **이내**(<=)
3. `tests/` 파일이 바뀌지 않았는가
